# Resume project writing

Select and express projects as proof of capability, not as a catalog of tools.

## Evidence first

For each project, establish its purpose, the candidate's personal contribution, collaborators or ownership, users or audience, technical approach, constraints, date/status, links, and observed outcome. Do not claim team work as individual ownership. Do not infer production scale, users, performance, awards, or deployment from a repository or screenshot alone.

## Choose and draft

- Select projects that add evidence missing from work experience or that are directly relevant to the target role.
- Use a clear project name, relevant technologies only when they help interpretation, and one to three concise bullets.
- Explain the problem or goal, the candidate's contribution, important implementation decisions, and a verifiable outcome where available.
- Name the candidate's role precisely for collaborative projects: for example, “built the API layer” rather than “built the platform.”
- Link only to public, working material the candidate authorizes (repository, demo, publication, or portfolio). Remove secrets, private endpoints, and sensitive customer information from both text and linked artifacts.

## Output

Return ready-to-place project entries plus a brief note identifying unverified claims or links to check. Hand LaTeX placement and formatting to `$overleaf-resume-authoring`.
